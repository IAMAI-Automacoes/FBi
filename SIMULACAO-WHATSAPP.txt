SIMULAÇÃO DO WHATSAPP — GUIA COMPLETO (CAPTURA, BANCO E TELA)
=============================================================

Atualizado em 01/10/2026 (tela /whatsapp pronta).

O que é: uma tela no painel onde o dono do restaurante vê as conversas do
WhatsApp do restaurante como se estivesse no próprio WhatsApp: o que o cliente
mandou, o que o EasyFeed respondeu sozinho e o que o dono digitou no celular.
Cada restaurante vê só as conversas dele.

Tudo está pronto e em produção: a captura (webhook, n8n, tabela, bucket de
arquivos) e a tela /whatsapp do painel (item 11). Este documento explica de
onde vêm os dados, o que significa cada campo, como cada tipo de mensagem é
desenhado e onde está cada parte do código.

Tudo aqui foi conferido com eventos reais, mandados pelo número do Camelo
(restaurante 11) em 30/09: texto, edição, exclusão, reação, resposta, áudio,
imagem, PDF, figurinha, gif e emoji.


-------------------------------------------------------------
1. CAMINHO DOS DADOS
-------------------------------------------------------------

  WhatsApp do restaurante
     -> uazapi (instância do restaurante)
     -> webhook da instância "registro-mensagens"
     -> n8n, workflow "Simulação Whatsapp"
     -> Supabase:
          tabela public.mensagens_whatsapp   (uma linha por mensagem)
          bucket privado "mensagens"         (fotos, áudios, PDFs...)

O front SÓ LÊ. Ninguém grava nessa tabela pelo site; quem grava é o n8n com a
chave de serviço. A política de segurança (RLS) já garante que o dono só
enxerga linhas do restaurante dele.

Existe um segundo webhook na mesma instância, o "easyfeed", que é o fluxo de
feedback. Ele é independente deste e não deve ser mexido por causa da tela.

2. CONFIGURAÇÃO (o que já está feito e como refazer)
-------------------------------------------------------------

2.1 Webhooks da uazapi (por instância; o webhook global está DESLIGADO)

  Cada instância tem dois destinos:

  a) Feedback
     url:             https://n8n-n8n-main.tikvpg.easypanel.host/webhook/easyfeed
     events:          ["messages"]
     excludeMessages: ["wasSentByApi", "isGroupYes"]

  b) Registro (é o desta tela)
     url:             https://n8n-n8n-main.tikvpg.easypanel.host/webhook/registro-mensagens
     events:          ["messages", "messages_update"]
     excludeMessages: []   (não exclui nada: grupos e mensagens do sistema entram)

  Quem configura: a edge function whatsapp-instancia, na ação "iniciar"
  (função configurarWebhooks). Toda instância nova já nasce com os dois, e uma
  instância antiga ganha os dois quando reconecta. Ela só adiciona o que está
  faltando, nunca duplica.

  Para adicionar na mão: POST {BaseUrl}/webhook, header "token: <token da
  instância>", body:
    { "action": "add", "enabled": true, "addUrlEvents": false,
      "addUrlTypesMessages": false, "url": "...", "events": [...],
      "excludeMessages": [...] }

2.2 Secrets do Supabase (Edge Functions)

  N8N_FEEDBACK_ENTRADA     URL do webhook easyfeed
  N8N_REGISTRO_MENSAGENS   URL do webhook registro-mensagens
  MIDIA_SECRET             segredo que o n8n manda no header x-midia-secret
                           para a função guardar-midia (o valor está com o
                           Raver; não vai para o repositório)

2.3 Edge functions

  whatsapp-instancia   cria/conecta a instância e configura os webhooks
  guardar-midia        baixa o arquivo do link temporário da uazapi e salva
                       no bucket "mensagens". Sempre responde 200: se der
                       erro, devolve { caminho: null, erro } e a mensagem é
                       gravada assim mesmo, só sem o arquivo. Limite de 40 MB.

2.5 Workflow do n8n "Simulação Whatsapp"

  Ligações:
    Recebe evento -> Acha o restaurante -> Classifica o evento -> Qual ação?
    Qual ação? "inserir" -> Tem mídia?
    Qual ação? "editar"  -> Aplica edição
    Qual ação? "status"  -> Atualiza status
    Tem mídia? verdadeiro -> Baixa a mídia -> É áudio?
    Tem mídia? falso      -> Grava mensagem
    É áudio? verdadeiro -> Converte para arquivo -> Transcreve -> Guarda a mídia
    É áudio? falso      -> Guarda a mídia
    Guarda a mídia -> Junta a mídia -> Grava mensagem

  O que cada node faz:
    Recebe evento          webhook POST, path registro-mensagens
    Acha o restaurante     Supabase, restaurantes onde whatsapp_token = body.token
                           (Always Output Data ligado)
    Classifica o evento    código: transforma o evento da uazapi em uma das
                           três ações (inserir / editar / status) ou descarta
    Baixa a mídia          POST {BaseUrl}/message/download com id, return_link,
                           generate_mp3 e return_base64 (só para áudio).
                           Timeout de 30 s, On Error = continuar
    Converte para arquivo  base64Data -> audio.mp3 (audio/mpeg), On Error = continuar
    Transcreve             OpenAI, transcrição de áudio, idioma pt,
                           On Error = continuar. O nome do node PRECISA ser
                           "Transcreve": o "Junta a mídia" procura por esse nome
    Guarda a mídia         POST na função guardar-midia com o header
                           x-midia-secret e a credencial Supabase do n8n.
                           On Error = continuar
    Junta a mídia          coloca midia_url, midia_mime, midia_caminho e
                           transcricao na linha
    Grava mensagem         POST /rest/v1/mensagens_whatsapp?on_conflict=restaurante_id,message_id
                           com Prefer: resolution=ignore-duplicates. Se a uazapi
                           mandar o mesmo evento duas vezes, não duplica
    Aplica edição          PATCH texto + editada_em na mensagem original
    Atualiza status        PATCH status, com filtro que impede o status de voltar
                           (um "entregue" atrasado não apaga um "lido")

  Princípio: erro de mídia ou de transcrição nunca pode fazer a mensagem
  sumir. Na pior das hipóteses a linha existe sem arquivo ou sem transcrição.


-------------------------------------------------------------
3. A TABELA public.mensagens_whatsapp
-------------------------------------------------------------

Uma linha por mensagem (reação também é uma linha, ver abaixo). A chave
natural é (restaurante_id, message_id), que é única.

  id                   bigint, chave interna
  restaurante_id       restaurante dono da conversa
  message_id           id da mensagem no WhatsApp (ex.: 3EB0C8C73637AC7BC4BA23)
  chat_id              a conversa. Pessoa: 5511932903005@s.whatsapp.net.
                       Grupo: 120363404511985129@g.us
  telefone             só dígitos. Em conversa individual é o telefone do
                       cliente; em grupo é o telefone de quem mandou
  nome_exibicao        nome DA CONVERSA: nome do contato, ou nome do grupo.
                       Em grupo, o nome de quem mandou cada mensagem está em
                       payload->message->>senderName
  de_mim               false = recebida (cliente mandou)
                       true  = enviada pelo número do restaurante
  por_api              só faz sentido com de_mim = true:
                       true  = o EasyFeed mandou sozinho (resposta automática)
                       false = o dono digitou no celular
  grupo                true se a conversa é um grupo
  tipo                 text, image, video, gif, audio, document, sticker,
                       reaction, location, contact, outro
  texto                texto da mensagem, ou legenda da mídia. Nulo em reação.
                       Se foi editada, já é o texto NOVO
  transcricao          texto do áudio (OpenAI). Nulo se não for áudio ou se a
                       transcrição falhou
  reacao               emoji, quando tipo = reaction. Nulo numa linha de
                       reação = a pessoa REMOVEU a reação
  responde_message_id  em resposta (citação): id da mensagem citada.
                       Em reação: id da mensagem reagida
  midia_caminho        caminho do arquivo no bucket "mensagens"
                       (restaurante_<id>/<message_id>.<ext>). É ESTE que a tela usa
  midia_url            link temporário da uazapi. Morre em ~2 dias. NÃO USAR
  midia_id             id para baixar de novo na uazapi (uso interno)
  midia_mime           tipo do arquivo (image/jpeg, audio/mpeg, application/pdf...)
  midia_nome           nome original do arquivo (vem em documento; em foto e
                       áudio normalmente é nulo)
  status               só em mensagem enviada (de_mim = true). Só avança:
                       SENT -> DELIVERED -> READ -> PLAYED (áudio ouvido).
                       DELETED = apagada para todos (vale para qualquer lado)
  editada_em           preenchido quando a mensagem foi editada
  enviada_em           horário real da mensagem no WhatsApp. ORDENE POR ESTE
                       (nunca por id ou criado_em: eventos chegam fora de ordem)
  payload              o evento cru da uazapi, como chegou. Útil para casos
                       raros (nome do remetente em grupo, localização, texto
                       antes da edição). Não exibir inteiro na tela
  criado_em            quando a linha foi gravada
  atualizado_em        última mudança (status, edição)

Índices prontos para as duas consultas da tela:
  (restaurante_id, chat_id, enviada_em desc)   abrir uma conversa
  (restaurante_id, enviada_em desc)            lista de conversas / período

Tipos TypeScript: src/lib/supabase/types.ts, tabela mensagens_whatsapp.

4. ARQUIVOS (fotos, áudios, PDFs...)
-------------------------------------------------------------

O bucket "mensagens" é PRIVADO (tem foto e documento de cliente). A tela gera
uma URL assinada na hora de exibir:

  const { data } = await supabase.storage
    .from('mensagens')
    .createSignedUrl(m.midia_caminho, 3600)          // 1 hora
  // data.signedUrl

  Várias de uma vez (melhor para abrir uma conversa):
  const { data } = await supabase.storage
    .from('mensagens')
    .createSignedUrls(caminhos, 3600)

  Para baixar documento com o nome original:
  .createSignedUrl(m.midia_caminho, 3600, { download: m.midia_nome ?? true })

Quem pode ler: só o dono, só a pasta restaurante_<id do restaurante dele>.
Atenção: o admin da plataforma enxerga as LINHAS de todos (pela tabela), mas
NÃO consegue abrir os arquivos (a política do bucket é só do dono).

Se a mídia falhou (link expirado, arquivo acima de 40 MB, uazapi fora do ar),
a linha existe com midia_caminho nulo. Mostre "Mídia indisponível".

5. CONSULTAS
-------------------------------------------------------------

Sempre filtre por restaurante_id, mesmo com RLS: o admin da plataforma enxerga
todos os restaurantes e, sem o filtro, veria tudo misturado.

Abrir uma conversa (as 100 mais recentes):

  supabase.from('mensagens_whatsapp')
    .select('id, message_id, chat_id, telefone, nome_exibicao, de_mim, por_api, grupo, tipo, texto, transcricao, reacao, responde_message_id, midia_caminho, midia_mime, midia_nome, status, editada_em, enviada_em')
    .eq('restaurante_id', restauranteId)
    .eq('chat_id', chatId)
    .order('enviada_em', { ascending: false })
    .limit(100)

  Não peça a coluna payload na listagem (é o evento inteiro, pesado). Busque só
  quando precisar, e só da linha que precisa.

Lista de conversas: função public.conversas_whatsapp(p_restaurante_id) —
uma linha por conversa, com a última mensagem e as não lidas:

  supabase.rpc('conversas_whatsapp', { p_restaurante_id: restauranteId })

  Não lida = mensagem RECEBIDA (sem reação, sem apagada) depois do que for
  mais recente entre: a leitura no painel (mensagens_whatsapp_leitura.lido_ate)
  e a última mensagem que o DONO mandou pelo celular (de_mim e não por_api —
  quem respondeu, leu; a resposta automática do EasyFeed não conta).
  É security invoker: a RLS vale, outro restaurante volta vazio.

Leitura: tabela mensagens_whatsapp_leitura (restaurante_id, chat_id,
lido_ate). Quem grava é a função whatsapp-instancia, ação "marcar-lidas"
{ chat_id }: ela também manda o "lido" para o WhatsApp de verdade
(POST /message/markread na uazapi) — o cliente vê os tiques azuis.

Tempo real: LIGADO (Realtime do Supabase, com REPLICA IDENTITY FULL). A RLS
vale também aqui: cada dono só recebe eventos do restaurante dele.

  const canal = supabase
    .channel(`mensagens-${restauranteId}`)
    .on('postgres_changes', {
      event: '*',
      schema: 'public',
      table: 'mensagens_whatsapp',
      filter: `restaurante_id=eq.${restauranteId}`,
    }, ({ eventType, new: linha }) => {
      // INSERT: mensagem nova (inclusive reação).
      // UPDATE: mudou status, foi editada ou apagada. Substitua pelo id.
    })
    .subscribe()
  // ao sair da tela: supabase.removeChannel(canal)

Uma linha MUDA depois de criada (status, edição, exclusão), então trate
INSERT e UPDATE. O evento traz a linha inteira, inclusive o payload; ignore
essa coluna no estado da tela.

6. COMO DESENHAR CADA MENSAGEM
-------------------------------------------------------------

Lado do balão
  de_mim = false -> esquerda (cliente)
  de_mim = true  -> direita (restaurante)
  Na direita, diferencie: por_api = true -> selo pequeno "Automática"/"EasyFeed";
  por_api = false -> mensagem do dono pelo celular.

Tiques (só em de_mim = true)
  SENT       um tique cinza
  DELIVERED  dois tiques cinza
  READ       dois tiques azuis
  PLAYED     áudio ouvido (WhatsApp mostra o microfone azul)
  nulo       sem tique

Editada
  editada_em preenchido -> "Editada" ao lado do horário. O texto já é o novo.
  O texto antigo está em payload->message->>text da própria linha (se um dia
  quiserem mostrar o histórico de edição).

Apagada
  status = DELETED -> balão "Esta mensagem foi apagada", sem o conteúdo.
  O texto/arquivo original continua guardado no banco; NÃO mostre por padrão
  (é o que o WhatsApp faz).

Reação (tipo = reaction)
  NÃO é um balão. É um emoji pendurado embaixo da mensagem reagida
  (responde_message_id). Regras:
    - para cada (mensagem reagida, lado de_mim) vale a reação MAIS RECENTE
      por enviada_em;
    - se a mais recente tem reacao nula, a reação foi removida;
    - se a mensagem reagida não está no banco (é anterior à captura),
      ignore a reação.
  Na lista de conversas, pode virar "Reagiu 👍 a uma mensagem".

Resposta (citação)
  texto normal com responde_message_id preenchido. Mostre o quadro de citação
  em cima do balão com o trecho da mensagem citada (busque pelo message_id na
  mesma conversa). Se não achar: "Mensagem não disponível".

Texto (tipo = text)
  Respeitar quebras de linha. Se o texto for SÓ emoji (1 a 3), o WhatsApp
  mostra grande e sem balão; ex.: /^(\p{Extended_Pictographic}️?‍?){1,3}$/u
  O WhatsApp também usa *negrito*, _itálico_, ~riscado~ (opcional).

Áudio (tipo = audio)
  midia_mime = audio/mpeg (mp3, já convertido do ogg do WhatsApp). Player
  <audio controls> e, embaixo, a transcrição (pode ser recolhível). Se
  transcricao for nula, só o player.

Imagem (tipo = image)
  <img> com a URL assinada; clique abre grande. Legenda em texto.

Vídeo (tipo = video)
  <video controls>. Legenda em texto. (Não testado com envio real ainda, mas
  segue o mesmo caminho da imagem.)

Gif (tipo = gif)
  É um MP4 sem som (o WhatsApp converte todo gif em vídeo). Renderize como
  <video autoplay loop muted playsinline> SEM controles, como o WhatsApp faz.

Figurinha (tipo = sticker)
  image/webp (pode ser animada; o navegador toca sozinho). Sem fundo de balão,
  uns 150 px.

Documento (tipo = document)
  Cartão com ícone pelo midia_mime, midia_nome e botão de baixar.

Localização / contato / outro
  Não testados. Mostre "Localização", "Contato" ou "Mensagem não suportada".
  Os dados ficam em payload->message->content.

Grupos (grupo = true)
  Ficam JUNTO com as outras conversas, na mesma lista, ordenados pela última
  mensagem (decisão do Raver). Mídia de grupo é baixada e guardada como
  qualquer outra.
  O título da conversa é nome_exibicao (nome do grupo; também vem em
  payload->message->>groupName). Em cada balão de terceiros, mostre o nome de
  quem mandou (payload->message->>senderName, ou o telefone).

Datas e horários
  Use enviada_em, no fuso America/Sao_Paulo. Separadores "Hoje", "Ontem" e
  data, como no WhatsApp.

Telefone
  Vem só com dígitos (5511932903005). Formate: +55 (11) 93290-3005.

Foto de perfil
  Não é guardada. O payload->chat tem "image"/"imagePreview", mas são links do
  WhatsApp que expiram. Use iniciais do nome como padrão.

7. O QUE ACONTECE COM CADA MENSAGEM (teste real de 30/09)
-------------------------------------------------------------

  Cliente manda o feedback "a comida estava fria..."
    -> linha text, de_mim false
  EasyFeed responde "Agradecemos muito pelo seu feedback..."
    -> linha text, de_mim true, por_api true, status SENT
    -> depois chegam "entregue" e "lido": status vira DELIVERED, depois READ.
       Um "entregue" atrasado chegou depois do "lido" e foi ignorado
  Cliente manda "oi" e edita para "olá"
    -> linha text "oi"; o evento de edição atualiza para "olá" e preenche
       editada_em (não cria linha nova)
  Cliente manda "tudo bem?" e apaga para todos
    -> linha text "tudo bem?"; a exclusão muda status para DELETED
  Cliente reage 👍 ao feedback
    -> linha reaction, reacao 👍, responde_message_id = id do feedback
  Cliente responde ao feedback com "oi"
    -> linha text "oi", responde_message_id = id do feedback
  Áudio
    -> linha audio; arquivo restaurante_11/<id>.mp3 no bucket; transcrição
  Foto
    -> linha image; arquivo .jpg
  PDF "Rec de It de Quimica.pdf"
    -> linha document; arquivo .pdf; midia_nome com o nome original
  Figurinha
    -> linha sticker; arquivo .webp
  Gif da biblioteca do WhatsApp
    -> linha gif; arquivo .mp4
  Mensagem só com 😎
    -> linha text "😎"

  Eventos que são descartados de propósito: "FileDownloaded" (é o eco do
  próprio download que o n8n faz) e status desconhecidos.

Dados para testar a tela: restaurante 11 (Camelo) tem essas 13 mensagens de
teste, na conversa 5511932903005@s.whatsapp.net, e mensagens reais de um grupo
de promoções. As 13 de teste foram gravadas antes do workflow existir, por
isso o áudio delas está sem transcrição; mensagens novas já vêm com ela.

8. O QUE A TELA NÃO CONSEGUE MOSTRAR
-------------------------------------------------------------

  - Conversas e mensagens anteriores a 30/09/2026 (a captura começou aí).

  - Mandar mensagem pela tela: a tela é SÓ de visualização, por decisão do

    pessoal do dono naquela conversa (item 9).


-------------------------------------------------------------
9. BOTÃO "ENVIAR MENSAGEM" (abre o WhatsApp PESSOAL do dono)
-------------------------------------------------------------

A tela não envia nada. Para falar com o cliente, o dono usa o WhatsApp
PESSOAL dele: o mesmo número dos avisos urgentes (restaurantes.whatsapp_dono).
Nunca o número de feedbacks do restaurante, por dois motivos:
  - os avisos urgentes saem do número do restaurante para o do dono;
  - com a API oficial, o número de feedbacks deixa de estar em qualquer
    celular — não dá para conversar por ele.
O banco garante que os dois números são sempre diferentes (gatilho
trg_restaurantes_numero_dono_diferente; o onboarding e as configurações
explicam e recusam; a conexão do WhatsApp recusa o número do dono).

Fluxo: o dono clica no contato (cabeçalho da conversa) -> painel do contato
(nome, telefone formatado) -> botão "Enviar mensagem" -> abre o WhatsApp
do dono na conversa com aquele cliente.

Consequência: essa conversa NÃO aparece na simulação (acontece fora do
número de feedbacks). Na simulação fica o feedback e o que veio pelo
número do restaurante. E o agente de feedback não interfere nela.

Quando NÃO mostrar o botão (ou mostrar desabilitado):
  - grupo = true (link de WhatsApp não abre grupo);
  - telefone nulo;
  - whatsapp_dono nulo -> botão desabilitado com o texto
    "Cadastre seu WhatsApp em Configurações para falar com clientes"
    (link para /configuracoes#whatsapp). Nunca cair no número do restaurante.

Número do cliente no link: a coluna telefone (só dígitos, já com 55).

TEXTO PRONTO
O cliente não conhece o número pessoal do dono. O link já leva uma
apresentação, que o dono confere e envia:
  "Oi, <nome_exibicao>! Aqui é do <nome_restaurante>. Vi sua mensagem e
   queria conversar com você."
(sem nome do cliente: "Oi! Aqui é do ..."). Vai em &text=, codificado com
encodeURIComponent.

ABRIR O APP CERTO
O link só escolhe PARA QUEM a mensagem vai, nunca DE QUAL número ela sai:
sai da conta aberta no app que o link abrir. Então:

  Mostre sempre o número de onde ela deve sair:
    "Abrir no seu WhatsApp (11) 91234-5678"

  Android (Chrome)
    Hoje (uazapi) o número do restaurante costuma estar no MESMO celular do
    dono, num dos dois apps. Abra o OUTRO app. A função whatsapp-instancia,
    na ação "status", devolve:
      business:   true se o número do restaurante é WhatsApp Business
      plataforma: aparelho do número do restaurante (smba = Business
                  Android, android = WhatsApp comum Android, ...)
    business = true  -> abrir o WhatsApp comum (package=com.whatsapp)
    business = false -> abrir o Business   (package=com.whatsapp.w4b)
    business = null (desconectado/desconhecido) -> wa.me
    Link:
      intent://send/?phone=<telefone>&text=<texto>#Intent;scheme=whatsapp;package=<pacote>;S.browser_fallback_url=<wa.me codificado>;end
    Se o app não estiver instalado, cai no wa.me sozinho.

  iPhone
    Não dá para forçar com segurança. Use https://wa.me/<telefone>?text=<texto>.
    (whatsapp://send?phone=... abre o comum e whatsapp-smb://send?phone=...
    o Business, mas o segundo não é documentado oficialmente: só usar depois
    de testar num iPhone com os dois instalados.)

  Computador
    https://wa.me/<telefone>?text=<texto>. Abre o app do WhatsApp do PC ou o
    WhatsApp Web, o que estiver logado. O texto "Abrir no seu WhatsApp
    (11) 91234-5678" avisa qual conta precisa estar aberta.

  Com a API oficial: o número de feedbacks sai dos celulares e sobra só o
  WhatsApp do dono. Aí basta wa.me em todos os aparelhos.

Detectar o aparelho: /Android/i e /iPhone|iPad|iPod/i no navigator.userAgent;
o resto é computador.

10. REGRAS DO PROJETO QUE VALEM AQUI
-------------------------------------------------------------

  - Cada restaurante vê só as próprias conversas (RLS já cuida; mesmo assim
    filtre por restaurante_id).
  - O front não escreve em mensagens_whatsapp nem no bucket "mensagens".

  - Não usar midia_url na tela: expira em 2 dias.
  - A tela não envia nada pelo EasyFeed/uazapi. Responder é sempre pelo
